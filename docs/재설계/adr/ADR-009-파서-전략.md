# ADR-009: 전용 파서를 기본으로 하고, 처음 보는 파일만 LLM이 열 매핑을 제안한다

- **상태**: 채택
- **날짜**: 2026-08-31
- **관련**: FR-01, FR-02, [ADR-004](ADR-004-수집경로.md), `docs/향후_고도화.md` §3-1

## 맥락

2026-07-16 작성된 [향후_고도화.md](../../향후_고도화.md) §3-1이 파서 전략에 대해 다른 주장을 하고 있었고, 재설계 과정에서 이를 보지 못한 채 진행했다(경위는 §참고).

**7월 주장**
> *"양식마다 파서를 새로 짜야 함. 우리은행·토스·카드사가 추가될 때마다 개발 노가다. 사용자의 임의 파일은 영원히 다 못 커버."*
> *"파서를 LLM으로 대체. 사용자의 Claude가 어떤 CSV/XLS든 직접 읽어 **표준행**으로 변환해 앱에 넘긴다."*

**8월 설계 (FR-01/02)**: 기관별 전용 파서. 새 기관 = 함수 1개.

## 판단 — 절반은 옳고 절반은 위험하다

| 대상 | LLM에게 맡기면 |
|---|---|
| **값 추출** (금액·날짜) | ⚠️ **위험** — 환각 시 `52,300`이 `5,230`이 되어도 탐지 불가. **재현성도 없다**(같은 파일이 다르게 읽힐 수 있음) |
| **구조 판단** (어느 열이 날짜·금액·가맹점인가) | ✅ **유리** — 파일당 1회, 틀리면 즉시 드러남, 사람이 확인 가능 |

12년치 금융 데이터를 다루면서 **값 추출을 확률적 모델에 맡길 수 없다.** 품질목표 **Q3(데이터 신뢰성)** 정면 위반이다.

## 결정

```
알려진 기관 (우리은행·우체국·KB·오빠두)
      → 전용 파서            무료·정확·재현 가능

처음 보는 파일
      → [LLM] 앞부분 몇 줄로 열 매핑 제안       ← 파일당 1회
      → [사람] 매핑 확인·수정
      → [코드] 그 매핑으로 값을 결정론적 추출    ← 환각 불가
      → 매핑을 프리셋으로 저장                  → 다음부터 LLM 호출 0
```

**LLM은 "읽는 법"을 판단하고, 실제 읽기는 코드가 한다.**

## 근거

1. **값의 정확성이 최우선이다.** 금액 하나가 틀리면 집계·잔액 정합성·NSM이 모두 오염된다.
2. **v1에 이미 구조가 있다.** `ImportPreset.column_mapping`(JSONB)이 정확히 이 용도다. v1은 사람이 매핑을 지정하게 했고, 우리는 **LLM이 초안을 제시하고 사람이 확인**하게 하면 된다. [ADR-001](ADR-001-v1-확장.md)에서 "그대로 살린다"로 분류한 자산이 여기서 값을 한다.
3. **FR-02를 유지하면서 7월의 우려를 해소한다.** 알려진 기관은 파서로 정확하게, 모르는 파일에서도 막히지 않는다.
4. **비용이 한 번뿐이다.** 매핑을 저장하므로 같은 양식의 두 번째 파일부터는 LLM을 호출하지 않는다.

## 뉘앙스 판단도 매핑에 포함한다

7월 문서가 지적한 실제 버그 — KB 파일의 `구분` 열이 `취소`/`취소된거래`인데 `parse_kb`가 그 열을 읽지 않아 **취소 거래가 지출로 저장**된다 — 는 열 매핑 문제이기도 하다.

```
column_mapping = {
  date: 0, amount: 4, merchant: 2,
  status: 8,                          ← 취소 여부 열
  status_rules: { "취소": "skip", "취소된거래": "skip" }
}
```

→ **FR-34**(취소·이체 거래 식별)로 SRS에 반영한다.

## 결과

- ✅ 값 추출의 결정론성 보장
- ✅ 임의 양식에서 막히지 않음
- ✅ v1 `ImportPreset` 자산 활용
- ✅ LLM 비용이 양식당 1회로 한정
- ⚠️ 매핑 확인 UI가 필요 (v1 `ImportView`에 미리보기 흐름이 이미 있음)
- ⚠️ LLM이 제안한 매핑을 사람이 확인하지 않고 넘기면 이 ADR의 안전장치가 무력화된다 → **확인을 건너뛸 수 없게** 설계한다

## 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| **전면 LLM 파싱 (7월안)** | 값 추출의 재현성·정확성을 보장할 수 없다. 금융 데이터에 부적합 |
| **전용 파서만 (8월안)** | 처음 보는 양식에서 막힌다. 기관이 늘 때마다 개발이 필요 |
| 사람이 매번 매핑 지정 (v1 방식) | 동작하지만 비개발자에게 부담. LLM 초안이 그 부담을 줄인다 |
