# ADR-008: 분류 체계는 공유하고, 추가는 열되 삭제는 막는다

- **상태**: 채택
- **날짜**: 2026-08-30
- **관련**: FR-12, FR-29~32, [ADR-003](ADR-003-분류판정을-데이터로.md), NSM

## 맥락

SRS 초안까지 우리는 **"분류를 어떻게 맞힐 것인가"**(4계층 엔진)만 정했고, **"분류 체계를 누가 어떻게 소유·변경하는가"** 는 비어 있었다. 이건 구현 세부가 아니라 요구사항이며, 세 가지가 여기에 걸려 있다:

1. **NSM 측정 가능성** — 분류 체계가 계속 바뀌면 *"어제의 85%와 오늘의 85%가 다른 것을 잰다."* 개선을 증명할 수 없다.
2. **12년치 데이터의 보존** — 분류를 지우면 그 분류를 쓰던 거래가 고아가 된다.
3. **v1과의 근본적 차이** — v1은 데이터가 없는 상태(cold start)를 전제해 *"사용자가 자유롭게 만들기"* 로 풀었다. v2는 132개 분류와 8,521개 매핑이 **이미 있다.** 전제가 뒤집혔으므로 해법도 달라야 한다.

## 실측 — 분류는 계속 늘어난다

`지출` 원장 22,047건에서 각 분류의 최초 등장 연도를 집계했다:

| 연도 | 신규 분류 |
|---|---|
| 2018 | 69 (초기 구축) |
| 2019~2024 | 2~13개/년 |
| 2025 | **19** |
| 2026 | 6 |
| **8년 누적 추가** | **63개 (연평균 7.9개)** |

`환불`, `손실(사기)`, `과태료`, `양도소득세` — **예상 못 한 사건이 생기면 분류가 늘어난다.** 미리 다 정의해둘 수 없는 성격이다.

→ **분류 추가는 필수 기능이다.**

## 그리고 2025년 폭증의 정체 — 자금 주체 축의 부재

2025~2026년 신규 29개 중 **22개가 `(동현)` 접미사**였다:

```
café(동현)  교통비(동현)  군것질(동현)  편의점(동현)  외식(동현)
의류(동현)  약값(동현)   화장품(동현)  스터디카페(동현)  … 22개
```

아빠가 아들 카드를 관리하기 시작하면서 **기존 분류를 통째로 복제**하신 것이다. 엑셀에 주체를 구분할 축이 없어, 분류명에 접미사를 붙이는 것 외에 방법이 없었다.

| | 엑셀 (현재) | `bearer` 축 도입 후 |
|---|---|---|
| 분류 수 | 132개 | **약 110개** (중복 22개 통합) |
| 주체가 늘면 | **분류가 또 22개씩 증가** | **0개 증가** |
| 주체별 집계 | `외식` + `외식(동현)` 수동 합산 | 축으로 조회 |

**`bearer`는 "있으면 좋은 축"이 아니라 분류 체계 폭증을 막는 구조적 장치다.** 그리고 이 22개는 프로젝트를 시작한 바로 그 시점(아빠 카드를 받은 때)에 생겼다 — **아빠도 같은 문제를 겪고 계셨고, 엑셀의 한계 안에서 푸신 것뿐이다.**

## 결정

| # | 항목 | 결정 |
|---|---|---|
| **D1** | 소유 | **공유 체계 1개** |
| **D2** | 편집 | **추가 ✅ / 이름수정 ✅ / 삭제 ❌ (비활성만)** |
| **D3** | 깊이 | **5단계 고정** |
| **D4** | 변경 시 과거 데이터 | 거래는 **분류 id를 참조** → 이름을 바꿔도 안전. 비활성화해도 과거 거래는 유지 |
| **D5** | 태그 | **`Won't`** |
| **D6** | 미사용 170개 | **비활성 상태로 이관** (자동분류 후보에서 제외, 되살리기 가능) |

## 근거

**D1 — 공유**: 아빠는 **이미 공유 체계로 운영해왔다.** 하나의 분류 체계 안에 아빠 것과 아들 것이 함께 있다. 우리는 그것을 `분류 × bearer` 두 축으로 **분해**할 뿐이다. "합치자"가 아니라 **"원래 하나였던 것을 올바르게 표현하자"** 이다.
부수 효과: 8,521개 매핑을 두 사용자가 공유하므로 **cold start가 없다** (v1의 문제가 재현되지 않는다).

**D2 — 삭제 금지**: 삭제하면 그 분류를 쓰던 거래(예: `기타식료품` 2,664건)가 고아가 되거나 조용히 사라진다. **품질 목표 Q3(데이터 신뢰성)** 정면 위반이다. 비활성화하면 새 거래에는 안 쓰이고 과거는 보존되며 되돌리기도 쉽다.

**D5 — 태그 배제**: 아빠는 12년간 태그 없이 운영했다. 횡단 축이 필요한 자리는 `bearer`(주체)와 `kind`(소비/비소비)가 이미 덮는다. v1의 태그는 **cold start 시절의 유연성 장치**였고 전제가 사라졌다.

## 파생 — 새 분류는 LLM만 맞힐 수 있다

```
새 분류 "구독서비스" 추가
  ① 이력 매칭    과거 데이터 없음  → ❌
  ② 사업자번호   규칙 없음        → ❌
  ③ 키워드 규칙  없음             → ❌
  ④ LLM         분류 목록을 받음  → ✅
```

→ **LLM에 전달하는 분류 목록은 항상 최신이어야 한다** (FR-31).
→ **분류 추가 직후에는 자동 분류율이 일시적으로 하락한다.** 이는 측정 오류가 아니라 정상 동작이므로, NSM 해석 시 감안한다.

## 결과

- ✅ 분류 체계가 안정적이어야 NSM이 의미를 갖는다는 전제를 충족
- ✅ 12년치 데이터가 분류 변경으로부터 보호됨
- ✅ `bearer` 도입으로 분류 22개 통합, 향후 폭증 차단
- ✅ 두 사용자가 매핑 자산을 공유 → cold start 없음
- ⚠️ 분류 추가 시 LLM 프롬프트 갱신이 필요 (FR-31)
- ⚠️ 공유 체계이므로 한쪽의 분류 변경이 다른 쪽에 보인다 — 사용자 2명뿐이고 같이 살므로 수용 가능

## 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| **사용자별 분리 체계** | 내 쪽에 cold start 발생(v1 문제 재현). 8,521개 매핑을 절반만 활용. 학습 데이터가 나뉘어 정확도 하락 |
| **공통 뼈대 + 개인 확장** | 유연하나 집계·권한이 복잡해진다. 1단계에는 사용자가 한 명뿐이라 당장 이득이 없다 |
| **v1처럼 자유 편집(삭제 포함)** | 데이터가 없던 시절의 해법. 지금은 자산을 훼손하고 NSM 측정을 무의미하게 만든다 |
