# ADR-007: AI 질의 연동을 MVP 이후로 미루고, 집계 API로 선택지를 열어둔다

- **상태**: 채택
- **날짜**: 2026-08-29
- **관련**: RQ-17, R-3, [ADR-005](ADR-005-LLM-교체가능-인터페이스.md), [ADR-006](ADR-006-자각-보존.md)

## 맥락

지금까지 엑셀의 **약점**(수기 분류·성능·시각화)만 다뤘다. 그러나 엑셀의 **최대 강점**을 정면으로 다룬 적이 없다:

```
엑셀   : 피벗·수식으로 무엇이든 계산할 수 있다
우리 앱 : 미리 만든 화면만 볼 수 있다
```

*"지난 3년간 명절 전후 2주 지출이 평소 대비 얼마나 늘었나"* 같은 질문은 화면으로 만들 수 없다. **이 격차가 전환의 진짜 장벽**이며, 화면을 더 만들어서는 넘을 수 없다. AI 질의가 유일하게 현실적인 대체 수단이다.

원래 구상은 **MCP 서버**를 만들어 아빠가 Claude Cowork에서 질의하는 것이었다.

## 조사 결과 — 클라이언트 선택이 네트워크 아키텍처를 결정한다

| 클라이언트 | Local MCP | Remote MCP | 우리에게 미치는 영향 |
|---|---|---|---|
| **Cowork** | ❌ 불가 | ✅ | **서버를 공인 인터넷에 노출해야 함** + OAuth + 상시 가동 |
| **Claude Desktop** | ✅ | ✅ | Local이면 노출 불필요 |

Remote MCP는 Anthropic **클라우드에서** 우리 서버로 접속한다(사용자 기기에서가 아니다). 따라서 서버가 공인 인터넷에서 도달 가능해야 하며, 사설망·VPN 뒤에서는 동작하지 않는다.

그리고 Local MCP는 `claude_desktop_config.json`의 `command`/`args`로 **로컬 프로세스를 실행**하는 방식(stdio)이라 **같은 PC 안**에서만 성립한다. URL로 내부망의 다른 PC를 가리킬 수 없다.

**제약**: 아빠가 쓰는 PC와 서버 데스크탑은 **다른 기기**다.
→ MCP 서버를 아빠 PC에서 실행하고 내부망으로 API를 호출하는 구성은 가능하지만, 아빠 PC에 런타임·패키징·설정이 추가된다.

## 핵심 관찰

세 가지 방식을 늘어놓으니 **공통분모가 드러났다**:

```
         ┌─ 앱 내장 채팅 ─┐
집계 API ┼─ MCP 서버 ─────┤   ← 무엇을 붙이든 이것이 공통
         └─ 화면·차트 ────┘
```

- MCP는 **"내가 만들지 않은 외부 AI 앱"** 을 붙이기 위한 표준이다. 우리는 앱을 직접 만들고 있으므로 필수가 아니다.
- 앱 안에서는 MCP 없이 **Tool Use(함수 호출)** 로 동일한 결과를 얻는다.
- 그리고 **분류 엔진용 LLM과 질의용 LLM은 같은 것**이다 ([ADR-005](ADR-005-LLM-교체가능-인터페이스.md)). 로컬 LLM을 띄우면 추가 인프라 없이 재사용된다.

## 결정

1. **지금 만든다**: **범용 집계 API** — 기간·분류·자금주체·집계축을 파라미터로 받는 형태. 화면 전용이 아니라 **질의 가능한 형태**로 설계한다.
2. **미룬다**: AI 연동 방식(앱 내장 채팅 / MCP 서버)은 **MVP 이후에 결정**한다.
3. **배제하지 않는다**: MCP는 집계 API를 감싸는 얇은 껍데기이므로 언제든 추가할 수 있다.

## 근거

- 지금 결정해도 **얻는 것이 없다.** 어느 쪽을 고르든 집계 API가 먼저 필요하다.
- Cowork를 택하면 **인터넷 노출 + OAuth + 상시 가동**이 강제되어 R-3(데이터 유출)가 급등한다. MVP 단계에서 감당할 이유가 없다.
- 앱 내장 방식은 아빠가 **설치할 것이 하나도 없다** — 이미 쓰는 웹앱에서 바로 질문한다. 온보딩 부담이 0이다.
- 로컬 LLM이면 아빠 금융 데이터가 외부로 전송되지 않는다.

## 결과

- ✅ 복잡한 네트워크·인증 결정을 MVP 밖으로 밀어냄
- ✅ 집계 API 하나로 화면·AI·MCP 세 소비처를 모두 대비
- ✅ 인터넷 노출을 지금 시점에서 피함 (arc42 §2 "내부망 한정" 전제 유지)
- ⚠️ 집계 API를 **처음부터 범용으로** 설계해야 함. 화면에 맞춘 전용 엔드포인트만 만들면 이 결정의 이점이 사라진다
- ⚠️ 노출이 필요해지는 조건(Cowork·모바일·자동화)이 생기면 **Step 4 수준의 보안 설계를 다시 해야** 한다

## 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| **Cowork + Remote MCP** | 인터넷 노출·OAuth·상시 가동을 MVP에 끌어들인다. 아빠는 집에서만 작업하므로 "어디서나"의 가치가 낮은 반면 비용이 크다 |
| **Claude Desktop + Local MCP** | 노출은 피하지만 아빠 PC에 런타임·확장 설치가 필요하고, 서버가 다른 기기라 구성이 한 단계 늘어난다. **MVP에서 감당할 이유가 없다** — 다만 유력한 후속 선택지로 남긴다 |
| **AI 연동 자체를 포기** | 엑셀의 자유 계산을 대체할 수단이 사라져 "엑셀 대체" 목표가 무너진다 |
