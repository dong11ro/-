# ADR-004: 수집은 사용자가 내려받은 파일 업로드로 한정한다

- **상태**: 채택
- **날짜**: 2026-08-26
- **관련**: R-6, H-4

## 맥락

핵심 가치가 "은행·카드 내역을 손대지 않고 가져오기"이므로 수집 자동화 수준이 제품 성패를 가른다. 네 가지를 검토했다.

## 검토 결과

| 경로 | 판정 | 근거 |
|---|---|---|
| **은행 웹 자동 스크래핑** | ❌ **배제** | ① 전자금융거래법 위반 시 5년 이하 징역·3천만원 이하 벌금, 은행 약관이 스크래핑을 별도 계약 서비스로 규정 ② 인증서·OTP·보안프로그램으로 사실상 불가, 은행 FDS가 자동 로그인을 탐지·차단 ③ **아빠 자격증명을 서버에 보관**해야 함 → R-3 극대화 |
| **오픈뱅킹 API** | ❌ **배제** | 개인은 테스트베드만 가능. 실서비스는 금융결제원 승인 + 최소 개인사업자 자격 + 보안점검 포함 천만원대 비용 |
| **결제 알림 수집** | ⏸ **보류** | 안드로이드는 가능하나 24시간 서버가 필요해지고 아빠 폰에 전달 앱 설정이 필요. 커버리지 문제는 아래로 해결되므로 MVP 제외 |
| **파일 업로드** | ✅ **채택** | 은행·카드 웹 다운로드 + 오빠두 템플릿(네이버·쿠팡) |

## 결정

**사용자가 직접 내려받은 파일을 업로드**하는 경로로 한정한다.
네이버페이·쿠팡은 **오빠두엑셀 템플릿의 출력 xlsx를 파서 하나로 받아들인다.**

## 오빠두 템플릿을 채택한 근거

은행 스크래핑과 **성격이 다르다**:

| | 은행 자동 스크래핑 | 오빠두(쿠키 재사용) |
|---|---|---|
| 자격증명 | 프로그램이 보관 | ❌ 보관 안 함 |
| 로그인 주체 | 프로그램 | **사람이 직접** |
| 법적 성격 | 자동화 부정접속 소지 | 본인 세션으로 본인 데이터 열람 |

전자금융거래법이 처벌하는 것은 **타인 명의 무단 접속**이며 여기 해당하지 않는다.
데이터 품질도 우월하다 — 은행 내역은 `네이버파이낸셜 50,000`이지만 오빠두는 **상품명·사업자번호·카테고리**까지 준다.

## 결과

- ✅ 법적·보안 리스크 최소
- ✅ 우리 서버에 쿠키가 오지 않는다 (템플릿 출력물만 업로드)
- ✅ 네이버페이 블랙박스 해소
- ⚠️ **마지막 한 단계는 반드시 사람 손이다** (H-4). 이 마찰은 규제상 제거 불가
- ⚠️ 오빠두 템플릿은 비공식 API 의존이며 2025-01 이후 미갱신 → **의존이 아니라 플러그인으로 격리.** 깨져도 은행 파일 경로는 생존해야 한다 (R-6)
- ⚠️ Windows 엑셀 전용이라 Mac 사용자(P1)는 직접 사용 불가
