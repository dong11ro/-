# ADR-001: v1.0.0을 재작성하지 않고 확장한다

- **상태**: 채택
- **날짜**: 2026-08-28
- **관련**: 리스크 R-5

## 맥락

v2 요구사항(RQ-01~16)을 v1.0.0(약 4,028줄)과 대조한 결과 **충족 2 / 확장 4 / 신설 8 / 결함 2**였다. 특히 `Account` 개념 부재, 자금 주체 축 부재, `Transaction` 평면 구조 등 핵심 테이블에 변경이 필요했다. "이 정도면 새로 짜는 게 낫지 않나"는 판단이 가능한 상황이었다.

## 결정

**확장(진화)한다.** 전면 재작성하지 않는다.

## 근거

1. **인프라·파이프라인·프론트 패턴이 그대로 유효하다.** 재작성하면 회고에 기록된 삽질 5건(한글 폴더명, node_modules 마운트 가림, CORS, 캐시 커밋, CSS 리셋)을 다시 겪는다.
2. **변경 범위가 테이블 3개 수정 + 3개 신설로 한정된다.** `importer.py`·`budget.py`·`ImportPreset`·`SavedFilter`는 손댈 필요가 없다.
3. **Alembic이 이미 있다.** 스키마 진화 경로가 확보되어 있다.
4. **v1을 한 번도 제대로 쓰지 않아 실데이터가 없다.** 스키마 대수술이 데이터 손실 없이 가능하다 — 실패가 자산이 된 경우다.

## 결과

- ✅ 기존 인프라·파서 레지스트리·차트 패턴을 즉시 활용
- ✅ Alembic으로 점진적 스키마 변경
- ⚠️ v1의 설계 결함 4건을 명시적으로 제거해야 한다 (ADR-003 등)
- ⚠️ v1 코드에 익숙해진 상태가 "이대로도 되겠지"라는 관성을 만들 수 있다 — RQ 대조표로 방어

## 기각한 대안

**전면 재작성** — 4,028줄이라 비용 자체는 낮지만, 얻는 것이 없다. 스택도 그대로 쓸 것이고 구조도 상당 부분 재사용하므로 순수한 손실이다.
