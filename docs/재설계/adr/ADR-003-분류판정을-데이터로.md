# ADR-003: 소비/비소비 판정을 코드가 아닌 데이터로 옮긴다

- **상태**: 채택
- **날짜**: 2026-08-28
- **관련**: RQ-03, v1 결함 ①

## 맥락

v1 `backend/app/kinds.py`:

```python
KIND_BY_TOP = {"저축": "saving", "투자": "investment", "이체": "transfer"}
def kind_of(top_name): return KIND_BY_TOP.get(top_name or "", "consumption")
```

**대분류의 "이름 문자열"로 소비/비소비를 판정한다.**

## 문제

1. **아빠 분류 체계로 교체하는 순간 전부 깨진다.** 아빠의 대분류는 `소비성지출 / 비소비성지출`이라 이 딕셔너리에 하나도 걸리지 않고, **전부 `consumption`으로 오판**된다.
2. 사용자가 카테고리 이름을 바꾸면 조용히 오작동한다. **에러가 나지 않아 발견되지 않는 종류의 버그**다.
3. 프로젝트 자체 설계 원칙 위반 — 명세서 1장 *"하드코딩 배제"*.

## 결정

`categories.kind` 컬럼(`consumption` / `saving` / `investment` / `transfer`)을 추가하고 `kinds.py`를 삭제한다.

## 근거

판정 근거가 **데이터에 있으면** 분류 체계를 통째로 갈아끼워도 안전하다. 아빠의 132개 분류를 이관할 때 각 분류에 `kind`를 부여하면 그만이다.

## 결과

- ✅ 분류 체계 교체에 안전
- ✅ 이름 변경이 로직에 영향을 주지 않음
- ⚠️ 이관 시 132개 분류에 `kind`를 지정하는 작업 필요 (아빠 대분류가 이미 소비성/비소비성이라 기계적)
