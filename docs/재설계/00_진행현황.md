## 현재까지의 핵심 결론

| 항목 | 결론 | 확정일 |
|---|---|---|
| 1차 타깃 | **아빠** — 12년 운영 파워유저 (비개발자이나 시스템 설계자 수준) | 08-25 |
| 제품 형태 | **엑셀 전면 대체를 목표로 점진 확장** (초기 불완전 감수) | 08-28 |
| 핵심 페인 | **가맹점명 → 분류코드 매핑** — 월 200건 중 약 136건 수동 (자동 매칭률 ~32%) | 08-28 |
| 자동화 전략 | **상위 30개 분류 = 건수 90%** 집중 자동화 / **롱테일 = 금액 81%** 는 사람 확인 유지 | 08-28 |
| 분류 체계 | 실사용 **132개** 유지 (마스터 302개 중 170개는 12년간 미사용). **단순화안은 데이터로 기각** | 08-28 |
| **North Star** | **자동 분류율 85%** 확정 (베이스라인 32% → 씨딩 45% → 목표 85%). 가드레일: 오분류율 ≤5%, 고액 100% 확인 | 08-30 |
| 도입 전략 | **2단계** — ①P1만 사용(아빠는 엑셀 유지) → ②아빠 전환. **R-8을 구조적으로 회피** | 08-30 |
| 마이그레이션 | **12년 전체 이관 기본.** 변환이 깨지는 구간이 나오면 그때 절단 (R-7 하향) | 08-30 |
| 수집 경로 | 은행/카드 파일 + 오빠두 템플릿(네이버·쿠팡). 스크래핑·오픈뱅킹은 배제 | 08-26 |
| **아빠의 목적** | *"지난달 소비를 되돌아보고 **쓸데없는 소비를 억제**"* — 수단(수기입력)이 아니라 목적 | 08-28 |
| 설계 원칙 P-1 | **자동화는 자각을 대체하지 않는다.** 분류는 제안으로, 사람이 훑는 흐름 유지 | 08-28 |
| 품목 단위 기록 | `Won't` → **`Must` 승격** — 상품 단위여야 "이건 필요없었네"가 나옴 | 08-28 |
| v1 코드 | **확장(진화) 채택.** 재작성 불필요. 테이블 3개 수정 + 3개 신설 | 08-28 |
| 품목 | **컬럼 하나(`item_name`)로.** 1:N 테이블은 영수증 OCR 때 (ADR-002) | 08-29 |
| 분류 엔진 | 이력 45%(정확 97%) + 사업자번호 + 규칙 + **LLM**. LLM 없이는 85% 불가 | 08-29 |
| LLM | **교체가능 인터페이스 + 정답셋 실측 후 확정** (ADR-005) | 08-29 |
| 기술 스택 | v1 유지(React·FastAPI·PostgreSQL·Docker) + pytest 신규 | 08-29 |
| 최우선 리스크 | **R-1** 아빠 전환 · **R-9** P1이 1단계에서 앱을 안 씀(v1 실패 재현) | 08-30 |
