# 가계부 프로젝트 회고 & 포트폴리오

> 개인용 가계부 웹앱을 **v1.0.0**까지 만든 기록. "무엇을 만들었나 + 어떻게 개발했나 + 무엇을 개선할까"를 한 문서에 담는다.

---

## 1. 프로젝트 개요

개인 재무를 기록·분석하는 풀스택 웹앱. 학습 + 포트폴리오 목적으로, 처음부터 제대로 된 3계층(프론트–API–DB) 구조와 확장 설계를 지향했다.

| 계층 | 기술 |
|------|------|
| 프론트엔드 | React + TypeScript + Vite |
| 백엔드 | Python + FastAPI + Pydantic |
| DB / ORM | PostgreSQL + SQLAlchemy + Alembic |
| 인프라 | Docker Compose (개발=Mac / 운영=Windows 홈서버 대비) |

**아키텍처**
```
브라우저(React) ──HTTP/JSON──▶ FastAPI ──SQLAlchemy──▶ PostgreSQL ──▶ Docker Volume
  6개 화면·SVG차트           집계·검증·파이프라인        영구 보존(코드와 분리)
```

**v1.0.0 기능 범위**
- **거래내역**: 입력·수정·삭제(모달·폼 컴포넌트 재사용), 다중선택 필터(팝업), 필터 즐겨찾기, 태그(다대다), 요약·날짜 그룹핑, 카테고리 색·출처·원본 가맹점 행 디자인
- **대시보드**: 현금 흐름(수입/소비/저축/투자/이체/순변화), 예산 현황, 상위 지출 카테고리, 가맹점 TOP, 지난달 대비 증감·튀는 지출, 월 이동
- **가져오기**: `.xls`/`.xlsx`/`.csv` 파싱(KB국민은행 양식), 가맹점 자동분류 규칙, 고정 마킹, 중복 감지, 기존 거래 규칙 재적용
- **분석**: 임의 기간(프리셋+직접), 월/분기/연 자동 버킷·월평균, 변동 예산(막대별 예산 틱), 카테고리 도넛·저축률 라인·요일별, 소비/비소비·고정/변동 구분
- **고정 지출**: 반복 템플릿 + 원클릭 입력
- **예산**: 총예산(독립) + 대분류별, 여유/임박/초과 색상, 매달 반복 + 그 달만 수정

**규모**: PR 23건, Alembic 마이그레이션 4개, 화면 6개, 백엔드 모듈 분리(analysis/dashboard/budget/importer/kinds/seed).

## 2. 개발 플로우 — "어떻게 만들었나"

### 방법론 파이프라인
```
브레인스토밍(개념·설계 대화)
   → 명세/결정
   → 수직 슬라이스로 분해 (기능 하나를 DB→API→화면까지)
   → 브랜치(feat/…) → 구현 → 3중 검증 → PR → 병합 → 태그
```

### 3중 검증 (매 슬라이스)
1. **백엔드**: `curl`로 API 숫자 확인 (프론트 없이 계산 검증)
2. **프론트 타입**: `tsc -b`로 컴파일 검증
3. **동작**: 브라우저에서 실제 확인

→ "계산이 맞나(백엔드)"와 "잘 보이나(프론트)"를 **분리**해 문제를 한 번에 하나씩 만났다.

### 핵심 원칙
- **Walking skeleton**: 새 배선은 가장 얇은 한 줄기로 먼저 관통시켜 검증(예: 필터를 카테고리 단일부터). 검증된 패턴은 골격 생략하고 묶어서 진행.
- **양방향/단방향 문**: UI·옵셔널 파라미터는 자유롭게(양방향), 스키마·실데이터는 신중(단방향, Alembic).
- **스키마 vs 데이터**: 컬럼이 이미 있으면 값만 backfill(마이그레이션 불필요), 컬럼 추가만 마이그레이션.
- **개념을 대화로 정립**: 소비/비소비(저축·이체), 고정/변동(통신비), 총예산 독립 같은 **모델을 코드 전에 토론으로 확정** → 갈아엎기 최소화.
- **GitHub Flow**: PR 하나 = 변경 하나. 안 끝난 작업 위에 쌓지 않기(겹침 방지).

## 3. 병목 & 개선/자동화

실제로 겪은 마찰과, 다음 프로젝트에서 **미리 하거나·자동화하거나·간략화할** 방법.

### 겪은 병목

| 병목 | 무엇이었나 | 개선안 |
|------|-----------|--------|
| **반복된 설계 토론** | 막대 버킷·예산선·소비/비소비/고정 축을 구현 중 여러 번 되돌아가 재설계 | 큰 화면 착수 전에 **데이터 모델·엣지케이스 먼저 확정**(브레인스토밍 스킬을 앞단에). "축(axis)"이 늘어날 낌새면 미리 목록화 |
| **수동 검증 루프** | 매 슬라이스마다 curl·tsc·브라우저 반복 | **검증 스크립트**(`make verify`: tsc + 핵심 엔드포인트 curl 스모크). 브라우저 확인만 사람이 |
| **시딩/마이그레이션 반복** | 카테고리·색·비소비 카테고리 backfill을 startup에 계속 추가 | 시드 데이터를 **선언적 파일(JSON/YAML)** 로 분리, backfill을 일반화(멱등 upsert 한 함수) |
| **삽질 ① 한글 폴더명** | `docker compose`가 프로젝트명 빈 값 에러 | 신규 프로젝트 템플릿에 `name:` 기본 포함 |
| **삽질 ② Dockerfile 인라인 주석** | `FROM x # 주석` 파싱 오류 | 린트/템플릿으로 방지 |
| **삽질 ③ node_modules 마운트 가림** | 볼륨이 컨테이너 node_modules 덮어씀 | compose 템플릿에 익명 볼륨 기본 |
| **삽질 ④ CORS / URL 인코딩** | 프론트↔백 출처 차단, curl 한글 400 | 템플릿에 CORS 미들웨어 기본, 검증 스크립트에서 인코딩 처리 |
| **삽질 ⑤ 캐시 커밋** | `.vite/`·`*.tsbuildinfo` 딸려 커밋 | **gitignore 프리셋**(Python/Node/Docker) 초기 포함 |
| **모달/레이아웃 CSS** | box-sizing 리셋 부재로 오버플로우 | 전역 리셋을 스타터에 |

## 5. 포트폴리오 하이라이트

### 잘한 기술 의사결정
1. **Docker 컨테이너화**로 Mac(개발)↔Windows(운영) OS 차이 흡수 — 배포 재현성.
2. **Alembic 마이그레이션 조기 도입** — 실데이터 쌓이기 전에 스키마 버전관리 확보(단방향 문 대비). 실제로 `is_fixed`·`saved_filters`를 데이터 보존하며 추가.
3. **입력 파이프라인 추상화**(명세 4장) — 수동/CSV/xls가 공통 정규화·검증·중복감지·저장을 거침. 새 경로는 파서만 추가.
4. **횡단 개념 모델링** — 카테고리(무엇)와 독립적으로 **소비/비소비**, **고정/변동** 축을 도입해 분석 정확도 확보. 규칙 하나로 셋 다 자동화.
5. **집계는 백엔드, 렌더는 프론트** — SVG 차트는 "값→좌표" 변환일 뿐, 무거운 계산은 DB(SUM·GROUP BY)에.

### 배운 점
- "작은 변경"과 "갈아엎기"를 가르는 건 **결합도·되돌림 가능성**. 대부분은 양방향 문이라 질러도 됨.
- 설계는 **대화로 먼저** 하면 재작업이 준다(막대 버킷·예산 모델이 그 사례).
- 가계부의 본질은 "현금 흐름"이라, 저축/투자는 소비와 분리해 두 관점(소비 분석 + 현금흐름)을 제공.
